# Dependencies, licensing and distribution

Version 0.2 | Owner: release/content reviewer

## Approval boundary

This is a production checklist, not a legal opinion or blanket license grant. Do not add a project-wide license or relicense existing user work without approval. Engine, libraries, weights, fine-tunes, datasets, art, music, voices and fonts can have different terms.

## Provenance

Record each shipped item's supplier/source, exact revision/hash, license text, notices, modifications, redistribution conditions, reviewer/date and package location. Public availability is not permission. Track generated/edited assets and evaluation/training data as well.

Gemma 4 provider documentation permits commercial use and identifies Apache 2.0 terms; verify the exact artifact and retain applicable notices. Runtime and weight licensing are separate. Sources S-001/S-002 in the [register](../references/VERIFIED_TECHNICAL_SOURCES.md) support that dated technology review, not rights for every third-party repack.

## Content review

Check distribution rights for art/audio/voices/model assets. Keep commercial sources and font files only in authorized storage, not this public repository. Research historical, medical and sensitive setting material before publication. Distinguish fictional test fixtures from factual educational claims.

The working repository name is not title/trademark clearance. Final name, rating and content approval depend on shipped material and need a product/release decision.

## AI disclosure

Steam's Content Survey distinguishes pre-generated and live-generated AI and asks about live-generation guardrails. Recheck the official requirements before submission; do not assume local execution is exempt. Source S-008 records this review. Describe actual production/runtime AI uses and limitations without promising perfect generated-text accuracy.

## Distribution

Provide a complete offline baseline or complete offline installer path including licensed required models/content. Optional enhanced packs cannot be necessary for core play or secretly change mechanics. Validate package authenticity, hashes, sizes and compatibility through the approved release process.

A dependency bill of materials accompanies releases. Vulnerability/license changes prompt review. Vendor accounts, credentials and purchases are separate authorized operations; this documentation change does not enroll the game in a store or purchase services.
